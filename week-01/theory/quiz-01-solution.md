## 문제 1: 블록체인 기초

블록체인의 핵심 목적은 무엇인가요? 중앙화된 데이터베이스와 비교하여 설명해주세요.

**답변:**
중앙 집중식 단일 서버나 관리자 없이도 분산형 네트워크 참여자들이 완벽하게 일치된 데이터를 안전하게 저장하고 검증할 수 있도록 하는 것이 핵심 목적입니다. 단일 관리자가 통제하는 중앙화 데이터베이스의 경우 악의적 조작이나 해킹에 취약하고 시스템 마비시 치명적입니다. 하지만 블록체인은 데이터와 상태를 노드 전체에 투명하게 분산시켜 권한을 공유하고 보안을 보장합니다.

## 문제 2: 이더리움의 특징

이더리움이 비트코인과 다른 점은 무엇인가요? 스마트 컨트랙트의 관점에서 설명해주세요.

**답변:**
비트코인은 최초의 암호화폐로서 안전한 가치 저장 및 단순 화폐 전송(스크립트 기반)에 집중하는 제한적인 용도로 만들어졌습니다. 반면, 이더리움은 튜링 완전성(Turing-complete)을 지원하는 EVM(Ethereum Virtual Machine)을 탑재하여, 블록체인 위에서 반복문이나 복잡한 조건 처리가 가능한 프로그램인 '스마트 컨트랙트'를 배포하고 실행할 수 있도록 하는 거대한 분산형 '월드 컴퓨터(World Computer)'로서 동작합니다.

## 문제 3: Solidity 기초

다음 Solidity 코드에서 `public`과 `view` 키워드의 의미를 각각 설명하세요.

```solidity
function count() public view returns (uint256) {
    return _count;
}
```

**답변:**
- `public`: 이 함수가 컨트랙트 외부(다른 컨트랙트나 EOA 트랜잭션 등)와 내부 어디서든 자유롭게 접근하여 호출될 수 있음을 나타냅니다. 
- `view`: 이 함수가 이더리움 블록체인의 상태(상태 변수 등)를 단지 '읽기(Read)'만 하고 어떠한 값도 변경/쓰기하지 않음을 보장합니다. 일반적인 조회 호출 시 가스비가 소모되지 않는 읽기 전용 함수 역할을 합니다.

## 문제 4: 상태 변수

Solidity에서 상태 변수(state variable)와 지역 변수(local variable)의 차이점을 설명하세요.

**답변:**
1) 상태 변수는 스마트 컨트랙트 영역 내에 선언되어 블록체인의 영구 저장소인 `Storage`에 기록됩니다. 트랜잭션이 종료된 후에도 데이터가 유지되며 변경 시 많은 가스비가 발생합니다.
2) 지역 변수는 함수 내부에서 선언되어 트랜잭션 실행 중에만 임시로 쓰이는 `Memory` 영역에 저장됩니다. 함수 실행이 완료되면 휘발되고 사라지며 연산 가스비만 들므로 훨씬 비용이 저렴합니다.

## 문제 5: Gas 개념

이더리움에서 Gas란 무엇이며, 왜 필요한가요?

**답변:**
Gas는 이더리움 네트워크에서 트랜잭션 및 스마트 컨트랙트 연산을 실행하기 위해 지불해야 하는 자원 사용의 측정 단위(비용)입니다.
1) 무한 루프 방어: 코드가 무한 루프나 악의적으로 너무 많은 연산을 소모하는 것을 방지합니다(지정된 Gas Limit 초과 시 즉시 중단).
2) 네트워크 남용 방지: 공짜라면 생길 수 있는 트랜잭션 스팸 공격(DDoS)을 가스 비용을 부과하여 경제적으로 불가능하게 만듭니다.
3) 노드 보상 제공: 상태를 연산하고 유지하는 검증자(Validator/Miner)들에게 인센티브 수수료 명목으로 지급하기 위해 반드시 필요합니다.
